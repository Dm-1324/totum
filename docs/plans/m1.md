# Milestone 1: Process skeleton

## Done when
UI sends a message to the agent and gets a reply; the agent has no way to touch the filesystem

## How we'll prove it
1. `pnpm dev`: type "hello" in the window, see `agent: hello` come back
   (ui -> preload -> main -> agent -> main -> ui). Host process shows as started.
2. `pnpm test` includes `packages/main/src/sandbox.test.ts`: spawns a process with
   the exact sandbox options main uses for the agent, and asserts that
   `fs.readFile`, `fs.writeFile` and `child_process.spawn` all fail with
   `ERR_ACCESS_DENIED`. (Structural half: `pnpm lint` already forbids the imports.)
3. `pnpm lint` green, plus a planted `node:fs` import in `packages/agent` fails it.

## Slices
1. [x] **Tooling + Electron.** Add `electron`, `electron-vite`, `vite` 7 (ADR 0002).
   `pnpm dev` opens an empty window. `main` only. Tests: none new; typecheck green.
2. [x] **IPC schemas** (adds `zod`; strict objects, 10k text cap) in `packages/shared/src/ipc/`: `chat.send` (ui->main, request
   `{text}` / reply `{text}`), `agent.message` / `agent.reply` (main<->agent,
   with `id` for correlation), `host.ready` (host->main event). Tests: round-trip
   parse / reject in `shared/src/ipc/*.test.ts`.
3. [x] **Agent + host utility processes.** main spawns both via `utilityProcess.fork`
   under a `Supervisor` (restart with backoff, gives up after 3 crashes in 60 s,
   `stop()` kills and waits on quit). `AgentClient` matches replies by id with a
   10 s timeout; unknown, duplicate and late replies are dropped and logged.
   `chat.send` reply became a result (`ok` / `code` + `message`) so the UI always
   gets an answer. Agent echoes (no model until M3); host announces `host.ready`.
   Tests: fake-child unit tests, a wiring test of `chat.send`, and real-process
   tests (Node `fork` stand-in) that nothing survives `stop()` or a crash loop.
4. [x] **Preload + UI.** Preload (CommonJS, sandboxed) exposes exactly
   `window.totum.sendMessage(text): Promise<ChatSendReply>`. React UI (ADR 0003)
   renders all text as text nodes; `pnpm lint` fails on `dangerouslySetInnerHTML`,
   `innerHTML` and other raw-HTML APIs in `packages/ui`. `chat.send` answers only
   our window's main frame on our page URL; the window can't navigate or open
   pop-ups. Tests: sender check (other window, iframe, foreign URL, gone frame),
   `untrusted_sender` from the handler, UI component incl. hostile HTML shown
   literally. Checked end to end in the built app over DevTools.
5. **Agent runtime sandbox.** The agent gets its own single-file bundle
   (`out/agent/index.js`, no shared chunks, all dependencies inlined) so the
   `--permission` read allow-list names exactly one file. Spawn it with Node's
   permission model (`--permission`, `--allow-fs-read` for that file only, no
   write, no child processes, no workers). `sandbox.test.ts` as above, plus a
   build check that the agent bundle imports nothing (no other files, no
   node_modules, no Node built-ins). ADR.
6. **Close-out.** Update `docs/progress.md`, run boundary-reviewer on the milestone diff.

## Boundary check
- `electron`: main (app, BrowserWindow, utilityProcess, ipcMain) and the preload
  (contextBridge, ipcRenderer) only.
  Agent and host get messages through `process.parentPort`, which is the utility-process
  API, not an `electron` import. Host may import electron later if needed; agent never.
- `zod`: shared (schemas); every receiver imports schemas from `@totum/shared`.
- `node:path`/`node:url` in main to locate bundles: main is allowed.
- New IPC messages: all in `packages/shared/src/ipc/`, validated with `safeParse` on receipt.
  ui only reaches main via the one named preload function; ui never sees agent or host.
- Agent payloads are strings only; no handles or functions cross.
- `react`, `react-dom`: ui only, no OS access. `@totum/shared` in ui: constants and types.
- `node:child_process` appears only in `main/src/supervisor.process.test.ts`, as a test
  stand-in for `utilityProcess`; spawning processes is main's job.
- Runtime: the permission-model flags make "agent can't touch the FS" true even if a
  forbidden import slipped past lint.

## Decisions needed
Settled with the user 2026-10-03; each gets an ADR in the slice that lands it.
1. **Build tool: `electron-vite`** (slice 1). One config for main, preload, renderer,
   plus extra entries for the agent and host bundles.
2. **Agent runtime sandbox: Node permission model** (slice 5). Spike first to confirm
   Electron's utility process honours `--permission`. Fallback if it doesn't: hidden
   sandboxed renderer (no Node at all), same IPC.
3. **UI framework: React** (slice 4, ADR 0003), JSX via Vite's esbuild; no
   `@vitejs/plugin-react` (its dev preamble conflicts with the CSP).

## Out of scope
- Direct agent<->host MessagePort, capability requests, grants, approvals, audit (M2).
- Model calls, streaming, budgets (M3).
- Global hotkey, command-bar styling, voice (M6).
- Packaging / installer, native modules (SQLite comes with M2).
